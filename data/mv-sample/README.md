# MV Sample — a minimal, committed RPG Maker MV test bed

A tiny RPG Maker MV project used to exercise the JavaScript-maker (MV) support
(`mruby-mvjs`). Unlike the RPG2k/XP test beds — complete third-party games
downloaded at build time — this project is **authored by us and committed** so
the maker has a controlled, deterministic gameplay bed with no external game
dependency.

## What's committed here

- `data/*.json` — the game database and one map, generated by
  `scripts/gen-mv-sample.py` (re-run it to regenerate). It defines a one-actor
  party, a 17×13 fully-walkable map, and a parallel-process event that sets a
  variable every frame (so a headless boot proves the map and the event
  interpreter run). Battle data (an enemy, a troop, Attack/Guard skills) is
  present but not auto-triggered.
- `index.html`, `js/plugins.js`, `js/main.js` — the project shell.

No graphics or audio are referenced (those would be copyrighted RTP assets), so
the map renders blank and the player is invisible. This bed tests the engine
and game **logic** — boot, scene flow, map/movement, the interpreter — not art.

## The engine is fetched, not committed

RPG Maker MV games need the engine core scripts (`js/rpg_core.js`, …) and PIXI.
Those are **not** committed; run

```
scripts/download-mv-corescript.bash
```

to fetch the **MIT-licensed** community corescript
([rpgtkoolmv/corescript](https://github.com/rpgtkoolmv/corescript)) and build
`js/rpg_core.js` … `js/rpg_windows.js` plus `js/libs/*` into this directory.
They are git-ignored (see `.gitignore`). CI runs the download before booting
the bed.

## Running it

```
scripts/download-mv-corescript.bash
./build/rpg_maker_clone --game_dir data/mv-sample
```
