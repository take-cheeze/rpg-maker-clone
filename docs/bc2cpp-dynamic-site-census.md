# bc2cpp dynamic-dispatch site census

How much by-name dispatch is left in the C++ that bc2cpp generates, why each site is still dynamic, and which proofs
remove it. This page records the method and the proofs, not counts: the counts change with every tree, so they are
regenerated by `scripts/bc2cpp/dynamic_site_census.rb` from the generated C++. History is in git.

## Method

```sh
mkdir -p /tmp/keep
MRBC=<host mrbc> BC2CPP_COVERAGE_KEEP_DIR=/tmp/keep ruby scripts/bc2cpp/coverage_report.rb > /dev/null
ruby scripts/bc2cpp/dynamic_site_census.rb /tmp/keep/shipped.cxx [--tsv sites.tsv]

# exact receiver origins (SiteOriginTable): the same pass also writes the origin table
MRBC=<host mrbc> BC2CPP_COVERAGE_KEEP_DIR=/tmp/keep2 BC2CPP_COVERAGE_ORIGIN_TABLE=/tmp/keep2/origins.tsv \
  ruby scripts/bc2cpp/coverage_report.rb > /dev/null
ruby scripts/bc2cpp/dynamic_site_census.rb /tmp/keep2/shipped.cxx --origins /tmp/keep2/origins.tsv [--tsv sites.tsv]
```

With the table, the generated `shipped.cxx` carries a `/*SO:<label>:<index>*/`
comment on every by-name line (the join key). Stripping those comments gives back
the untagged file byte for byte (checked when the numbers below were measured).

`shipped.cxx` is the `SKIP_UNSUPPORTED=1` pass of the whole-program wio build
(all three compiled gems, the shipped set). Two runs of the same tree are
byte-identical, so counts are comparable across revisions.

* **Call site**: one source line in a generated method body that calls
  `bc2cpp_send(M, recv, <index>, ...)`. The `<index>` is mapped back to a method
  name through `bc2cpp_sym_names`. The helper definitions are not counted.
* **Helper region**: everything before the first generated `*_impl` body. A
  by-name call there is *held by a helper*; it is reached from every generated
  site that calls the helper.
* Each site is classified by (a) its position (inside a known-class arm, in the
  else arm of an inline fast path, or bare), (b) the nearest preceding marker
  comment, (c) the `POLY_DIAG` line when the site has one, and (d) a heuristic
  for where the receiver register was last assigned.
* The categories in the "why" table are exclusive; the first matching rule wins
  (see `category` in the script).
* `--tsv` writes one row per body site (line, owner method, name, arity, fast-path
  flag or `class_arm`, marker family, guard shape, receiver origin, category,
  `POLY_DIAG` path). The owner tables are a grouping of the owner method's
  prefix; the "Now" numbers below were produced this way from `0a9adfc`.

## Proofs that remove dynamic sites

Each proof below is a sound fact about a receiver or a callee that lets a site call directly or keep a guarded fast
path. The implementation and its soundness argument live with the code named in each one.

- Exact receiver origins: the origin of each receiver is traced through the table the census writes (`SiteOriginTable`).
- Native results and receivers: RGSS native results, native receivers and native ivar families are typed from the native sources.
- Block sends: the class of a block's value, the block arm of a literal-block send, and the receiver flow of block sends.
- Containers and elements: element reads of mutable containers, element classes of frozen tables, and container receivers.
- Core bodies: exact receivers reaching the compiled core, the core-body helper closure, exported core bodies, and checked exact proofs in core bodies.
- Numeric operands: Fixnum and Integer constants, native `:int` arguments, interval operands, and tuple returns.
- Constructors: the class of a `new` site and the argument pools of constructors.
- Per-class resolution: proven receiver sets resolved per class, and closed-world helpers for arithmetic and comparison.
- Provable errors: error arms the proof shows unreachable, and post-call facts.
- Kept else arms: the interface tables and else arms the proof still needs, and why.

## Declarations

Return declarations (`-> C`) are checked facts, and parameter declarations are checked the same way; instance-variable
declarations are runtime guards, not facts. See `sig/bc2cpp/declarations.rbs` and `docs/bc2cpp-type-check.md`.
