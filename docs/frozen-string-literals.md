# Frozen string literals

A Ruby file that starts with `# frozen_string_literal: true` gets CRuby's frozen
string literals in the embedded mruby, both interpreted and compiled by bc2cpp.
The design is ADR 0546 (`docs/adr/0546-persistent-frozen-string-literals.md`).

## What the comment does

- A plain string literal is a frozen String: `"abc".frozen?` is `true`, and
  `s << "x"` raises `FrozenError`.
- Each frozen literal is one object per VM: two loads of the same literal are
  `equal?`, and so are two literals with the same bytes. Each VM has its own
  objects.
- The literal objects live until the VM closes. They are not freed by the
  collector.
- The literal forms covered are plain literals, heredocs without interpolation,
  and `%w` / `%W` words without interpolation.
- Interpolated strings, `dup`, `+` and substrings are not frozen.
- The comment is honoured only in the comment lines before the first token. The
  key is `frozen_string_literal` with `true` or `false`, case-insensitive, with
  `-` and `_` treated alike. A line such as `# -*- frozen_string_literal: true -*-`
  also works.
- `eval` compiles its own string and does not inherit the flag.
- Files without the comment compile to the same bytecode as before.

## Known differences from CRuby

- `singleton_class` on a frozen literal raises `FrozenError`. CRuby allows a
  singleton class on a frozen String. The collector depends on this refusal.
- A literal's identity is per content per VM, not per source position. Two
  literal sites with the same bytes share one object, as in CRuby.

## bc2cpp

The compiled path emits `mrb_frozen_literal(M, bytes, length)` for each frozen
literal site. `BC2CPP_FROZEN_LITERALS=0` makes bc2cpp emit the old fresh String
for those sites. This is a kill switch for the compiled output only; the
interpreter still freezes the literal. A file without the comment generates the
same C++ with or without the switch.

## Checks

`ruby scripts/bc2cpp/frozen_literal_persist_check.rb` (CI: the bc2cpp runtime
checks) needs `MRBC` and `BC2CPP_MRUBY_FULL`. It covers the interpreted and
compiled parity, `FrozenError` on mutation, identity across collections, two VMs
in one process, the flag on an unrooted String and the kill switch.

`docs/frozen-string-literal-audit.md` is a separate report: it classifies the
engine's own mutating calls on literals and is generated by
`scripts/rpg2k/frozen_literal_reach_check.rb`. The engine's `mrblib` files do not
use the comment, so that report is unchanged by this feature.
