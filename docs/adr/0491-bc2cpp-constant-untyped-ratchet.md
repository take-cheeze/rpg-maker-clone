# 491. An untyped engine constant is a type-check error unless it is on a reviewed list that only shrinks

Date: 2026-10-19

## Status

Accepted. Its review gate was removed (ADR 0522).

## Context

The bc2cpp type check (ADR 0412, docs/bc2cpp-type-check.md) types every constant the analysis can prove: a class pool,
a literal, an integer constant, an array sum or a constructed class. Those that it cannot type stay untyped, and the
summary only counts them (`constants typed N of M`). Nothing fails when a new constant is untyped, so the count can
rise without anyone noticing, and a constant that becomes typed never prompts anyone to tell the check it is resolved.

ADR 0226 (NOMETHOD_REVIEWED) and ADR 0275 (PROVEN_MISS_REVIEWED) already gate a closed-world finding on a reviewed
list: a finding not on the list is a build error, and a listed entry that no longer occurs is a stale error. Both keep
the list in a generated Ruby file (`tools/bc2cpp/*_reviewed.rb`), regenerated by a script and checked by a fixture
check.

## Decision

The type check reports TC1017, an error, for the constants the ratchet judges (engine constants only):

* an untyped constant whose name is not in `CONSTANT_REVIEWED` (`tools/bc2cpp/constant_reviewed_list.rb`);
* a listed name that is now typed, or is no longer an engine constant of the program.

The list is generated by `scripts/bc2cpp/constant_reviewed_update.rb` from the engine's own type check, run as CI runs
it (`type_check.rb --no-sends` under the closed-world build's host mrbc). `--write` regenerates it; the diff is printed
first, and an analysis that produced no constants refuses to write, so a silent failure cannot empty the list.
`scripts/bc2cpp/constant_reviewed_check.rb` fixes the gate's behaviour on fixture programs and checks that the list file
is in its generated form. The gate runs in CI's `bc2cpp-build` job through the existing Type check step.

The constant typing rules are not changed here. Typing a constant is a separate change, and it is what shrinks the list.

## Consequences

* A new untyped engine constant fails CI until it is typed or reviewed and listed. Reviewers see the name and its
  file:line in the diff of the list.
* A typed constant forces its entry out of the list in the same change, so the list can only shrink.
* The list is only as current as the closed world it was generated from. A different submodule set or mrbc build can
  give a different untyped set, so the list must be regenerated under the CI closed build (docs/bc2cpp-type-check.md).
* The gate judges names, not the constant's site. Two engine constants with the same name share one row in the facts
  (`const_rows` keeps the first), so they are judged as one.
* Program-level `--files` runs are not gated by default, so a user's own program is not held to the engine's list.
