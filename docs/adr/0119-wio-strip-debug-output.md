# 119. Strip $stderr.puts diagnostic calls out of wio's compiled Ruby with a Ripper-based rewrite

Date: 2026-09-09

## Status

Accepted

## Context

ADR 115/117/118 already stripped every *compiler-level* debug artifact
`enable_debug` adds for wio (mrbc's `-g`, `MRB_DEBUG`, the `lv` table).
What's left is different in kind: real diagnostic statements hand-written
into the game/engine Ruby itself. Grepping `mruby-rpg2k`/`mruby-rgss`/
`mruby-lcf`'s `mrblib` found 194 `$stderr.puts` call sites (`mruby-lcf` has
none) -- error/failure diagnostics inside `rescue` and guard branches
("common event N not found", "BGM playback failed: ..."), plus
`RGSS.warn_once`/`warn_stub`, a shared wrapper most of them don't even call
`$stderr` directly for. Each is a real string-literal pool entry plus
dispatch opcodes, unobservable on `env:wio_rgss_boot` today for the same
reason `MRB_DEBUG`'s asserts were (ADR 117): no serial console wired up.

Asked earlier whether a RuboCop-style tree rewriter would be safer than a
text-based (grep/sed) removal here. Real evidence in this exact codebase
says yes on both counts a naive approach gets wrong:

- **Multi-line statements.** `mruby-rpg2k/mrblib/interpreter.rb`:
  ```ruby
  $stderr.puts '[RPG2k] Call Event: "this event" has no map event to ' \
               'refer to (running inside a common event)'
  ```
  A backslash-continued statement across two lines -- a line-oriented
  regex either misses the continuation (leaving a dangling string-literal
  statement behind, still valid Ruby but silently *wrong*: an orphaned
  expression statement whose value is simply discarded, not a syntax
  error) or has to special-case it.
- **`p`/`pp` are not always `Kernel#p`/`Kernel#pp`.** Grepping for bare
  `^\s*p ` to catch `Kernel#p` calls the same way instead matches real code
  like `mruby-rpg2k/mrblib/game.rb`'s `p = @pauses[@released]` -- a local
  variable named `p`, coincidentally the single most common local-variable
  name a regex-based "strip debug prints" pass would go looking for. A
  blind text match would have deleted real assignments.

## Decision

**`strip_wio_debug_output.rb`** (new, repo root): given an input/output
path, tokenizes the source with `Ripper.lex` (stdlib -- this project has no
existing Gemfile to add `parser`/`rubocop-ast` to for a fuller AST, and
Ripper's own token stream is enough for what this needs), scans for a
`$stderr` `GVAR` token immediately followed by a `.puts` -- by real token
type, not text match, so a string that merely *contains* the substring
"$stderr.puts" is never touched -- and only when `$stderr` is the first
thing on its own line (a bare statement; the one call embedded in a larger
expression anywhere in this codebase today, `scene/battle.rb`'s
`.each { |l| $stderr.puts ... }`, is left alone by this check, moot anyway
since that whole file is already excluded from wio's `rbfiles` since ADR
107). Extends the removed span forward while the line ends in `\`, to
correctly take the whole statement in the multi-line case above. A hard
safety net either way: the rewritten source is re-parsed with
`Ripper.sexp` before being accepted, and the script refuses to write a
rewrite that fails to parse (leaving the original file's own content
untouched) rather than risk shipping broken Ruby.

**`build_config.rb`'s new `wio_strip_debug_rbfiles(spec)`**, called last in
`mruby-rpg2k`/`mruby-rgss`/`mruby-lcf`'s own `mrbgem.rake` (after every
other `spec.rbfiles` filter -- it replaces each surviving entry's path, so
anything that still needs to match an *original* path has to run first):
a no-op for every build but wio, and for wio replaces each gem's own
`rbfiles` with build-directory copies generated by a `file` task depending
on the original and the strip script -- the same generated-artifact
pattern ADR 109/110's own schema-blob/font-SD generators already
established, applied to hand-written source instead of data-driven
generation. **The checked-in `.rb` files themselves are never touched** --
desktop/wasm/psp keep every diagnostic line untouched, compiled exactly as
written.

### The real tradeoff, not swept under the rug

Unlike ADR 115/117/118's fixes (pure compiler/debugger metadata with zero
functional purpose on any target), these `$stderr.puts` calls are not
accidental cruft: `mruby-rgss/mrblib/error_report.rb`'s own file comment
explains a real, deliberately designed feature -- a `Tee` wraps `$stderr`
in a ring buffer of the last 200 lines, which `error_dump_report`
(`src/error_dump.cxx`) folds into a crash report the player can copy, and
which also feeds an on-screen terminal log console via
`RGSS.__log_bridge_write`. Every one of these call sites is that feature's
own input. Stripping them for wio means a future wio build that ever wires
up `error_dump_report`/a crash-report UI would get a *thinner* report than
desktop/wasm's -- this ADR trades that away for real flash today, on a
target where neither `error_dump_report` nor any crash-report UI exists
yet (the bring-up firmware's own error handling, `wio_rgss_boot_main.cxx`'s
`record_exc`/`build_ui`, shows only the exception's class name, never
touches this ring buffer at all). If a future session wires that feature
up for wio specifically, this ADR's own tradeoff is the first thing to
revisit.

### What was verified

- **Every rewritten file re-parses**: all 22 `.rb` files this touches
  (every file wio's three gems actually compile, after the debug-tools/
  battle/schema.rb exclusions already in place) processed with zero
  failures, checked directly with `Ripper.sexp` on each output.
- **The multi-line case specifically**: `interpreter.rb`'s two-line
  `$stderr.puts` above is removed cleanly, no dangling fragment, confirmed
  by inspecting the rewritten method body directly.
- **The `p = ...` false-positive risk**: confirmed no bare `puts`/`p`/`pp`/
  `print` diagnostic calls exist anywhere in this codebase at all (every
  `^\s*p ` grep hit is a local-variable assignment, e.g.
  `game.rb`'s `p = @pauses[@released]`) -- this rewrite only ever
  targets `$stderr.puts`, the one pattern real evidence supports removing.
- **`error_report.rb`'s own `Tee` install (`$stderr = Tee.new($stderr)`)
  survives untouched**: it's a global-variable assignment, not a `.puts`
  call, and the rewriter correctly leaves it (and the two doc-comment
  mentions of `$stderr` in `map.rb`) alone.
- A real relink, `env:wio_rgss_boot`, on top of ADR 118's state:

  | state | FLASH overflow | RAM used | RAM headroom (of 196,608) |
  | --- | --- | --- | --- |
  | ADR 118 (`lv` table strip) | 932,672 | 45,536 | 151,072 |
  | + `$stderr.puts` strip | **917,648** | **37,840** | **158,768** |

  **15,024 bytes of flash and 7,696 bytes of RAM** -- the RAM drop is a
  `.data` reduction (20,672 -> 12,976), the same "const struct landed in
  `.data`, not `.rodata`, on this toolchain" shape ADR 115/118 already
  found for debug-info structs, here for the string-literal pool entries
  these calls' arguments compiled to.

## Consequences

- Wio's flash overflow drops to 917,648, RAM headroom rises to 158,768
  bytes (80.7% of budget) -- both real, and both smaller than ADR 115's own
  win, matching expectations for 194 call sites' worth of strings and
  opcodes versus ~100 mrbc-wide debug tables.
- `strip_wio_debug_output.rb` and `wio_strip_debug_rbfiles` are reusable
  for the next diagnostic-call shape this codebase grows, without needing
  another codegen bug hunt: the token-matching logic is intentionally
  narrow (`$stderr.puts` only) because that's the one pattern real evidence
  in this repository supports today, not because the mechanism can't
  generalize.
- If `error_dump_report`/a crash-report UI is ever wired up for wio, this
  ADR's own tradeoff section is where to start.
