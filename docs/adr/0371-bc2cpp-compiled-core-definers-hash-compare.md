# 0371. A compiled-core definer view, and the Hash arm of the comparison helpers closed through it

Date: 2026-10-07

## Status

Accepted

## Context

The request was "compile all core methods too for a closed world". ADR 0264 compiled mruby's own Ruby, ADR 0269
lifted the block exclusion behind a Fiber guard, ADR 0350 admitted the Enumerator wrappers. Three facts of the
current tree differ from the premise of the request and shape what can be done:

1. **Almost everything already compiles.** In the wio closed-world measurement (`scripts/bc2cpp_coverage_report.rb`:
   all three engine gems, `core_gems: :canonical`, `SKIP_UNSUPPORTED=1`) 215 core-source bytecode methods are in the
   world and 190 compile clean (170 of them hidden definitions, see below); 5 more are shadowed by a later
   definition of the same owner and name, so they are not methods the interpreter ends with. 25 stay interpreted.
2. **A shipped closed-world build holds no core Ruby at all.** `psp`, `wio` and `maix` are the only closed-world builds
   and all three are hot-only (ADR 0214): `bc2cpp_closed_world_srcs` hands them `core_gems: nil` and
   `mruby-core-compiled` is an empty translation unit there. The world in which core bodies compile and the world in
   which the helper closure proofs run only meet in the measurement world above and in a build that sets
   `BC2CPP_HOT_ONLY=0` next to the closed world. Everything in this ADR is therefore inert in the three shipped
   firmware builds (no generated byte changes); it is exercised by the census world, the checks, and any future
   non-hot-only closed build.
3. **Core definitions are not registry definitions on purpose** (ADR 0264 finding 1). The closed-world proofs run on
   `registry.transform_values { |defs| defs.reject(&:core) }`; guarded and native-named core bodies are hidden
   definitions (`CodeGen.core_hidden_defs`). A helper therefore sees `Hash#<` as a *foreign Ruby* definer (the
   text scan of `outside_ruby_paths`) it cannot call, and keeps `mrb_funcall(M, a, "<", 1, b)` for it (ADR 0362).

## Findings: what stays interpreted, and why

`CoreMethods.interpreted_report` (printed by every run as `== core-source methods left interpreted (N) ==`, one
`Owner#name | reason | features` line each) gives the exact list. Wio closed world, shipped pass, base `8ab8aa75`:

| Reason (exclusive) | Count | Methods |
| --- | ---: | --- |
| mruby-enumerator: Fiber machinery (`CoreDefs.fiber_gem?`, not one of the seven audited wrappers) | 18 | `Enumerable#chunk` `#chunk_while` `#zip`; `Enumerator#__enumerator_block_call` `#each` `#each_with_index` `#initialize` `#initialize_copy` `#next_values` `#with_index` `#with_object`; `Enumerator.produce`; `Enumerator::Generator#each` `#initialize`; `Enumerator::Yielder#<<` `#initialize` `#yield`; `Kernel#to_enum` (and its alias `enum_for`) |
| builds a lambda (`CoreDefs.builds_lambda?`) | 3 | `Enumerable#inject`, `Hash#to_proc`, `Symbol#to_proc` |
| unsupported shape (codegen `#error`) | 3 | `File#initialize` (explicit `super`, optional arguments), `IO.open` (nested `ensure`/`rescue`: `unhandled opcode EXCEPT`), `IO.popen` (optional + `**opts` + `&block`) |
| refused by decision (`core_refused.txt`) | 1 | `Kernel#\`` (mruby-io's later `kernel.rb`, outside the compiled sources, is the live definition) |
| conditional def, names Fiber | 0 | |

The same 25 by language feature (a method may carry several): block 20, optional/rest/keyword arguments 13,
`rescue` 4, lambda 3, `super` 1, `method_missing` 0, none 1 (`Kernel#\``). By the grouping the request asked for: the
"blocks", "optional arguments" and "super with a known chain" refusals of ADR 0264 are lifted already (ADR 0269); what
remains is the Fiber exclusion (18), closures (3) and shapes the code generator cannot express (3).

## Decision

### Core methods that stay interpreted: nothing is lifted

Each remaining reason is a soundness boundary or a missing generator feature, not a cheap gate:

* `Yielder#<<`, `#yield`, `Generator#each`, `Enumerator#each` and the rest of the 18 run the generator on a Fiber or
  call `@proc.call(*args)`. The Fiber guard of ADR 0269 would hand a Fiber's frames to the bytecode, but the
  **root-context** frame would then run `@proc.call` of a compiled block, which is a cfunc `RProc` (ADR 0266) that
  `mrb_funcall(:call)` from a C frame cannot run (ADR 0269, CORE_PROC_CALL covers only a block *parameter*, not an
  ivar). `Kernel#to_enum` is body-clean but takes `**kwd`, a keyword-rest signature the generator rejects, the same
  wall as `IO.popen`.
* `Enumerable#inject`, `Symbol#to_proc`, `Hash#to_proc` return or build closures that may run after the frame is gone
  (ADR 0269 point 5); proving a lambda does not escape is a separate analysis.
* `IO.open` needs `EXCEPT` inside an `ensure` handler, `File#initialize` an explicit `super(...)` into a native
  `IO#initialize`; both are one-off file opens, not hot, and need generator features (nested handler regions, super
  dispatch from compiled frames) whose own proof obligations exceed this change.
* `Kernel#\``: compiling it would *replace* the live definition with one that raises.

`BC2CPP_ENUMERATOR_WRAPPERS=0` and the existing exclusions are unchanged, so the compiled-core counts do not move:
215 core-source methods, 190 compiled, 25 interpreted, before and after.

### CORE_COMPILED_DEFINERS: a view next to the registry

`CodeGen#core_compiled_definers(name)` (`tools/bc2cpp/codegen_core_compiled_cmp.rb`) answers `{owner => [definitions]}`
for the core-source methods this run compiles (hidden definitions and aliases included; it is `block_core_index`,
ADR 0270, keyed by name). `CallFacts::Answers` gains three questions that read it through the new
`World#compiled_core` callable: `foreign_definer?(name, owner)`, `compiled_foreign_owners(name)` and
`foreign_fully_compiled?(name)`. **`definers` and `members` are unchanged**, and the registry is not touched, so the
name-keyed proofs of ADR 0264 finding 1 see the world they always did. Census check on the same tree before and after
(markers in the generated TU): `FIXNUM_COMPARE` 907 / 907, `LITERAL` 226 / 226, `FIXNUM_BINARY` 222 / 222,
`INTEGER_UNARY` 109 / 109.

### The Hash arm of `< <= > >=`

`bc2cpp_slow_lt/le/gt/ge` (908 generated callers) kept one by-name call, for a Hash receiver (ADR 0362, 0367).
`CodeGen#core_compiled_hash_cmp_target(op)` now proves the compiled `Hash#<op` can stand in for it, when all of:

* `numeric_slow_closed_cmp?(op)` already holds (ADR 0362: closed world, `Comparable` and `Hash` the only foreign
  definers, no engine, module or singleton definer, `members` inside the model set, `<=>` untouched);
* the view has exactly one compiled `Hash#<op` and `Answers#foreign_definer?(op, 'Hash')` (the foreign definer the
  scan saw is the one compiled here);
* `block_core_target('Hash', %w[Hash Enumerable], op, 1, blockless: true)` resolves to it: no project definition, native
  registration, prepend, unattributed mixin, outside Ruby definer or computed installer on the lookup chain, the body
  compiles clean and this link emits its owner (the existing BLOCK_CORE_DIRECT gates, ADR 0270);
* **`YieldReach#yield_free?` holds for its body.** A direct `_impl` call skips the registered entry, so the entry's Fiber
  guard (ADR 0269) is not run, and the helper has no block to relax it with (ADR 0283). The body calls `all?` with a
  block that does `key?`, `[]` and `==` of stored values; the proof says no `==` reachable in this closed world
  can suspend a Fiber, so no yield can cross the frame. A program `==` that may yield turns the arm off.

The Hash branch of the closed helper becomes

    if (mrb_obj_ptr(a)->c != M->hash_class) return bc2cpp_nomethod_named(M, a, "<", 1, b);
    mrb_gc_arena_restore(M, ai);
    return Hash_$3c_impl(M, a, b);

an exact-class guard in front of the compiled body (a Hash subclass instance, which `members` already excludes from the
world, takes `bc2cpp_nomethod_named`, which dispatches by name before it raises, so a wrong proof is a
`closed-world proof violated` error or the right answer, never a wrong one). `BC2CPP_CORE_COMPILED_CMP=0` keeps the
by-name call byte for byte; the Complex/Rational `#if` arm is untouched. A per-gem run needs `Hash` in
`OTHER_OWNERS` for the `_impl` to be linkable (the same gate BLOCK_CORE_DIRECT uses), otherwise nothing changes.

### Not closed

* **`Numeric#zero?`** (`bc2cpp_slow_zero`, 33 callers): `members('zero?')` is unbounded because `File.zero?` and
  `FileTest.zero?` are native class methods whose owner the registration scan cannot read, so the receiver set is not
  bounded and the helper cannot prove a NoMethodError for the rest. A compiled `Numeric#zero?` would only answer the
  Numeric receivers.
* **`Enumerator::Yielder#<<`** (the `<<` helper, PR #2049's family): the Yielder bodies are not compilable (above), so
  there is no compiled definer to call, and `members('<<')` keeps `Enumerator::Yielder`.
* **`Hash#<` for a Hash whose `==` may yield**: stays by name (the yield-free proof is the condition).

## Consequences

Measured with `scripts/bc2cpp_coverage_report.rb` (`BC2CPP_COVERAGE_KEEP_DIR`) and `scripts/bc2cpp_dynamic_site_census.rb`
on the wio closed world, the same tree with `BC2CPP_CORE_COMPILED_CMP=0` as the base:

| Measure | Before | After | Delta |
| --- | ---: | ---: | ---: |
| core-source methods in the world / compiled / left interpreted | 215 / 190 / 25 | 215 / 190 / 25 | 0 |
| `bc2cpp_send` calls held in helpers | 17 | 13 | -4 |
| generated callers of a helper that holds a by-name call | 4,329 | 3,422 | -907 |
| `bc2cpp_send` call sites in generated bodies | 2,205 | 2,205 | 0 |
| `bc2cpp_nomethod` sites | 4,541 | 4,541 | 0 |
| **Sites that can reach by-name dispatch** (bodies + helper callers + 414 block + 30 funcall sites) | **6,978** | **6,071** | **-907 (-13.0%)** |
| `FIXNUM_COMPARE` / `LITERAL` / `FIXNUM_BINARY` / `INTEGER_UNARY` markers | 907 / 226 / 222 / 109 | 907 / 226 / 222 / 109 | 0 |
| generated `shipped.cxx` | 21,460,068 B | 21,460,856 B | +788 B |

The 907 sites are `lt` 296, `gt` 311, `le` 134, `ge` 166. The generated method bodies are unchanged. The by-name calls
that remain in the compiled `Hash#<` body (`key?`, `[]`, `==` of stored values) are counted with the compiled core
methods' own POLY sites, as before. The census has no size or time gate in `docs/ci.md`; the wio/psp/maix firmware size
budgets were not rebuilt, and cannot move: those builds are hot-only (Context point 2), the generated code for them is
byte-identical.

Verification, `scripts/bc2cpp_core_compiled_cmp_check.rb`: generated code for all four helpers (exact-class test, proof
violation arm, no by-name call, `_impl` declared before use, Complex/Rational arm unchanged); NEG worlds for
`Hash#<` and `#<=` reopened, a module prepended to Hash (with and without a comparison name), a user `==` that may
yield, a computed `define_method`, an alias, an outside Ruby `Hash#<`, a build without mruby-hash-ext, `method_missing`,
a singleton method, an open world, no core compile, and the kill switch; then 5,760 helper-versus-operator cases
(subsets, NaN and user `==` values, default procs, Hash subclasses as operands, non-Hash operands, nested hashes, a
full GC in the last round) on a full-core libmruby, all equal in value, exception class and message. The mutation check
(`scripts/bc2cpp_core_compiled_cmp_mutation_check.rb`) breaks the kill switch, the yield-free proof, the exact-class
test and the foreign-definer requirement; the lookup-chain walk is defense in depth that no negative world isolates
(every one is stopped earlier by `numeric_slow_cmp_proof`), so it has no mutant.

A bug found on the way: `CoreCompare.verified` sorted `[owner, file-or-nil]` pairs and raised `ArgumentError`
(comparison of Array with Array failed) when an outside Ruby source defined `Hash#<` outside the model's files; it is
nil-safe now.

Not run in this environment: the 32-bit `mrb_int` and no-bigint libmruby builds of `bc2cpp_numeric_slow_check.rb`
(no `BC2CPP_MRUBY_FULL32`/`BC2CPP_MRUBY_NOBIGINT`), the PlatformIO firmware builds and their size budgets, and the
desktop/Emscripten builds. The change adds no `mrb_int` conversion and no bigint literal (the arm passes `mrb_value`s
to a compiled body), so the AGENTS.md 32-bit rules do not apply to it.
