- **Wio Terminal: reverted `-flto` -- it was silently stripping the ARM
  reset/interrupt vector table from the linked binary, a real bug that
  would very likely have kept real hardware from booting at all despite
  linking cleanly and reporting a correctly-sized image.** Found by
  actually booting the linked firmware under this project's own Renode
  emulator (docs/adr/0094) rather than trusting linker output alone: every
  `-flto` build aborted on a wild jump moments after reset; GCC 14.2.1 and
  `-fmerge-all-constants` were each confirmed to boot correctly on their
  own. Root cause: PlatformIO's vendored Arduino/SAMD startup code
  references its vector-table array only via the linker script's `KEEP()`,
  never through a real call-graph edge -- exactly the shape LTO's own
  whole-program dead-code elimination discards before the final link ever
  gets a say. See docs/adr/0135 for the full investigation and the
  corrected flash numbers.
- **Wio Terminal: found a second, unrelated, more fundamental bug --
  `wio_rgss_boot` exhausts its entire RAM budget partway through loading
  the `mruby-rpg2k` gem's own generated bytecode, before user code ever
  runs.** Confirmed live under Renode with GDB attached: an `mrb_realloc`
  call for 384 bytes (growing a class's method table while defining one
  more method) fails and raises an uncaught `NoMemoryError` -> `abort()`.
  The heap had already grown 162,556 bytes past the end of `.data`/`.bss`,
  leaving only a 100-byte gap to the current stack pointer. This means
  `wio_rgss_boot`, as currently written, would not finish booting on real
  hardware even once flash size is fixed -- a new, confirmed blocker
  distinct from (and likely more consequential than) the flash-size
  question this whole series has focused on. See docs/adr/0135.
